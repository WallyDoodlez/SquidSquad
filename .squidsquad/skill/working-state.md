- **NEW: Pre-Phase-4 wizard migration writes to wrong path.** Cycle 1537 lesson. Originally Phase 3c was wizard.py migration to `deploy_alias_v2`. But `deploy_alias_v2` writes at `filename_suffix=".v2.md"` default (the v2 coexistence path) — wizard would start writing `CLAUDE.linked.v2.md` instead of the canonical `CLAUDE.md`. Phase 4 (suffix flip default `→ ""`) is what makes `deploy_alias_v2` write to canonical paths. So Phase 3c MUST land paired with Phase 4 as one atomic commit, OR Phase 4 lands first. Recipe: when migrating callers across a compatibility seam, audit what the seam's default produces TODAY vs the post-seam-removal world; if defaults differ, pair the caller-migration commit with the default-flip commit.
- **NEW: Check the actual error before assuming a failure category.** Cycle 1536 correction of cycle 1535. Cycle 1535's `--tb=line` output showed only ONE error ("Missing includes-events.yml for worker"); I extrapolated that to all 3 test_manifest failures since they all sit alongside Phase-1 manifest changes. Cycle 1536's `--tb=short` revealed the truth: only 1 of 3 was v1-coexistence; the other 2 (`agent-boundaries.md.md` and `l4-curation.md` orphan) are real pre-existing bugs with separate root causes. Lesson: when inventorying multiple failures, get the actual error message for EACH one before assuming a common cause. The cost of a 30-second `pytest --tb=short` beats the cost of mis-scoping a future cycle.
- **NEW: Phase 3 is too large for one commit; slice into 3a/3b/3c/3d/3e.** Cycle 1535 lesson. Initial Phase 3 plan was monolithic ("delete v1 deploy_role + _load_manifest + _resolve_includes + v1 hint emit"). Inventorying call sites revealed 90 v1 references across 16 test files + wizard.py production caller + catalog_drift.py — vastly larger blast radius than expected. The right move: split by category (test cleanup → wizard migration → code deletion → catalog_drift audit), commit each, run DS review per non-trivial slice. Phase 3a (test gate retirement) was the cleanest wedge — 8338 deletions, 0 additions, zero production code touched.

Code review finds bugs in code that EXISTS; deletion-only diffs have no surface for review. The "trivial fold-in" rule from cycle 1511 extends to deletions: when there's no new logic, the LLM-review overhead exceeds the finding rate.

The cycle_pre script auto-switched the agent from `skill/e6-v2-cutover-10685` to `main` because the agent boot expects to start on main.
