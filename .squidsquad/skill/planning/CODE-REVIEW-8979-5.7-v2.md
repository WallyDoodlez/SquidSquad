### Finding 1

- **File**: `references/scripts/squidsquad_cli.py`
- **Line**: 93 and 99 (inside `_api_call`)
- **Severity**: warning
- **Issue**: `_api_call` calls `sys.exit(1)` directly on `HTTPError` and `URLError`, which short-circuits the per-role aggregation loops in `start_team.py` (`cmd_boot`, `cmd_stop`, `cmd_reboot`). When the shim iterates over multiple roles and one API call fails at the transport/HTTP level, the entire process exits immediately — remaining roles are never attempted.
- **Evidence**: `_api_call` (line 87–100) terminates via `sys.exit(1)` before any return value reaches the caller. The `start_team.py` loops (e.g., `cmd_stop` at line 104–109, `cmd_boot` at line 65–71, `cmd_reboot` at line 87–93) are designed to aggregate per-role results across all targeted agents, but that aggregation can only operate on `_api_call` results that actually return — transport-level failures abort the loop entirely. For example, `--stop --all` against roles `["skill", "pm"]` where "skill" triggers an HTTP 500 would exit with code 1 without ever attempting to stop "pm". The exit code is still correct (1 = failure), but the behavioral contract of "stop all agents" is broken.
- **Suggested fix**: Replace `sys.exit(1)` in `_api_call` with raising a custom exception (e.g., `HarnessAPIError`), then catch it in each command function (`cmd_start`, `cmd_stop`, `cmd_restart`) and return 1. This allows the per-role loops in `start_team.py` to continue iterating over remaining roles and produce a complete aggregation. Alternatively, if abort-on-first-transport-error is the intended design, document this explicitly in the `cmd_*` docstrings and in `start_team.py`’s module-level exit-code contract so operators understand that transport failures halt all further role processing.
