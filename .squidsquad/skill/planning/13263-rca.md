## The mechanism — and a genuine remaining blocker
dm framed this as the behind-clone class, and the symptom fits: my #13170 branch never contained qa's later-added files, and the squash dropped them. BUT the precise GitHub mechanism does **not** match a naive squash model, and I want to flag the gap honestly rather than assert a fix on a false premise:

- `git_ops.pr_merge` uses **`gh pr merge --squash`** → GitHub computes the squash **server-side**.
- The standard model is: squash = `diff(merge-base(base, head), head)` applied to base tip.
- I verified (`git merge-base squidsquad/task/13170 origin/main` = `ce9aa7649`): **both the merge-base AND the branch HEAD LACK** QA-RESULTS-13215 (qa added it later, in `554f92517`, which is an *ancestor* of my squash). Under the standard model that diff doesn't touch the file → the squash should have KEPT base's copy, not deleted it.
- Yet `8fbfca4af`'s tree lacks it → a net deletion was recorded.

**Specific blocker:** GitHub's server-side squash produced a tree missing a file that neither the merge-base nor the branch head deleted. That contradicts the naive base...head model, so the exact trigger (how GitHub picks the squash base / resolves overlapping `.squidsquad/` paths when the PR branch is behind and the base advanced between PR-open and merge) needs **reproduction**, not just forensics. The remote branch was `--delete-branch`'d so its exact pushed tree is no longer inspectable on origin (only my local copy, which also lacks the file).

## Candidate fix directions (prevention — to validate against a reproduction)
1. **Make the PR branch current with base immediately before the squash** — in the harness `/merge` flow (or `git_ops.pr_merge`), `gh pr update-branch` (or merge origin/main into the branch) before `gh pr merge --squash`. If the branch HEAD contains the up-to-date `.squidsquad/` tree, the squash cannot drop those files regardless of GitHub's internal base choice. This is the most robust, mechanism-agnostic fix and is consistent with the team "merge main before merge" rule (#12495) + the behind-clone cluster (#13212/#13215/#13261/#13211).
2. **Scope the merge so it can never carry cross-clone `.squidsquad/` deletions** — weaker; doesn't address non-state files.
