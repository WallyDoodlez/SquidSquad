## Failure Details

### A4: .sh files have CRLF line endings

**Severity**: Medium — CRLF in .sh files causes `\r` errors when run on Linux/macOS.

**Root cause**: `compose.py` `boot_role()` function uses `output_path.write_text(content, encoding="utf-8")` at line 171 of `references/scripts/compose.py`. On Windows, Python's `write_text()` defaults to platform line endings (CRLF). The `.sh` template source file itself may have LF, but `write_text` re-encodes on write.

**Fix**: Change line 171 to use `newline='\n'` for .sh files:
```python
# For .sh files, force LF line endings
if ext == "sh":
    output_path.write_text(content, encoding="utf-8", newline="\n")
else:
    output_path.write_text(content, encoding="utf-8")
```

Alternatively, apply `newline='\n'` for both extensions since PS1 with LF also works fine.
