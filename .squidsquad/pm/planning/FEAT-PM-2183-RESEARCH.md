### 2.2 reboot_agent.py — Full Behavior Spec

New file: `references/scripts/reboot_agent.py`

```
Usage:
    python references/scripts/reboot_agent.py <role>
    python references/scripts/reboot_agent.py skill
    python references/scripts/reboot_agent.py --all
    python references/scripts/reboot_agent.py skill --timeout 300
    python references/scripts/reboot_agent.py skill --force
```

Behavior:
1. Resolve clone path for role (same logic as boot_remote._get_clone_path)
2. Check if agent is running (read `.pid`, check process alive)
   - If not running: print "agent not running", exit 0
3. Write `.restart` sentinel file for the role (content: "reboot requested by reboot_agent.py")
4. Wait for `current-state` to show `idle|` (poll every 2s, default timeout 300s)
5. If idle detected within timeout:
   - Kill the claude process (SIGINT on Unix, taskkill on Windows)
   - The wrapper detects exit, sees `.restart` sentinel, respawns
   - Print "reboot initiated for <role>"
6. If timeout exceeded:
   - Print "timeout waiting for idle — agent is busy"
   - Remove the `.restart` sentinel (don't leave stale sentinels)
   - Exit 1 (caller decides what to do)
7. `--force` flag: Skip idle wait, kill immediately. Wrapper sees sentinel, respawns.
8. `--all` flag: Iterate all roles from config.md, reboot each sequentially.

Exit codes:
- 0: reboot initiated (or agent not running)
- 1: timeout (agent busy, sentinel cleaned up)
- 2: usage error

Contents:
1. **Overview**: Agents do not manage their own lifecycle. The wrapper handles singleton, restart, and heartbeat. The reboot_agent.py script handles safe restart.

### 2.4 Heartbeat Mechanism

**Writer** (in simplified wrapper):
```bash
# Background heartbeat — write epoch to .health every 5s
(
  while true; do
    date +%s > "$HEALTH_FILE.tmp"
    mv -f "$HEALTH_FILE.tmp" "$HEALTH_FILE"
    sleep 5
  done
) &
HEARTBEAT_PID=$!
```

PowerShell equivalent:
```powershell
$heartbeatJob = Start-Job -ScriptBlock {
    param($healthFile)
    while ($true) {
        $epoch = [int][double]::Parse((Get-Date -UFormat %s))
        [System.IO.File]::WriteAllText("$healthFile.tmp", "$epoch")
        Move-Item -Force "$healthFile.tmp" $healthFile -ErrorAction SilentlyContinue
        Start-Sleep -Seconds 5
    }
} -ArgumentList $HealthFile
```

**Reader** (in simplified health_check.py):
```python
def check_heartbeat(role, clone_root):
    health_file = Path(clone_root) / ".squidsquad" / role / ".health"
    if not health_file.exists():
        return "dead", "no heartbeat file"
    try:
        epoch = int(health_file.read_text().strip())
        age = time.time() - epoch
        if age <= 10:
            return "alive", f"heartbeat {int(age)}s ago"
        else:
            return "dead", f"heartbeat stale ({int(age)}s ago)"
    except (ValueError, OSError):
        return "dead", "heartbeat unreadable"
```

**Advantages over current system:**
- No stale `.health` files — epoch is always recent or clearly stale
- No PID cross-check needed — heartbeat IS the liveness signal
- No mtime fallback path
- No auto-correction of stale files
- No status string parsing ("alive|boot_epoch=...", "backoff", "restarting", etc.)

### Side Effects and Risks

1. **Running agents during deploy**: If an agent is mid-cycle when templates change, it won't pick up new wrapper until restart. This is safe — old wrapper continues working until restart.

2. **Heartbeat file format change**: During transition, both old and new format files exist. health_check.py must handle both. Risk: false "dead" detection if health_check.py is updated before agents restart.
   - **Mitigation**: health_check.py tries int parse first, falls back to old format.

3. **watchdog.py removal**: If anyone manually runs `python scripts/watchdog.py`, it will fail.
   - **Mitigation**: This was a standalone process. Check if any cron/systemd/scheduled task runs it. On this project: no evidence of external watchdog scheduling.

4. **cycle_post.py restart sentinel**: Currently cycle_post writes `.restart` if `restart_needed: true` in cycle-output.json. In new model, agents should NOT request self-restart — only PM/DM/reboot_agent.py should. However, keeping this as a backdoor for template-change detection is acceptable.
   - **Decision**: Keep `_do_restart_sentinel()` in cycle_post.py for now. Document that agents should not use it.

5. **PM health check step**: Currently a no-op (watchdog handled it). Must become active again with new behavior. Risk: PM must now do work it wasn't doing.
   - **Mitigation**: Keep it simple — read context pressure files, run health_check.py, call reboot_agent.py if needed.

6. **.stop sentinel**: Current wrapper checks for .stop after each claude exit. New wrapper should keep this — it's a clean shutdown mechanism for humans.

### Edge Cases

1. **Agent crashes during reboot_agent.py wait**: reboot_agent.py is waiting for idle, but agent crashes. The wrapper restarts the agent (no sentinel), and reboot_agent.py sees a new session's current-state that may never go idle.
   - **Handling**: reboot_agent.py should also check if PID changes during wait (different process = agent already restarted, sentinel no longer needed).

2. **Two reboot_agent.py calls for same role**: First writes sentinel, second writes sentinel again (no-op, same file). Both wait for idle. First one's kill triggers restart. Second one sees new PID and should exit.
   - **Handling**: reboot_agent.py should record the PID at start and exit if PID changes.

3. **Heartbeat writer dies but claude still running**: The background heartbeat subshell could die independently. Health check would report dead, but agent is actually working.
   - **Handling**: Very unlikely (subshell is trivial). If it happens, wrapper's cleanup trap still fires on exit. Low risk.

4. **Windows file locking**: On Windows, `mv` of heartbeat file could conflict with health_check.py reading it simultaneously.
   - **Handling**: Use atomic write pattern (write .tmp, mv). Reader uses try/except. Same pattern as current code.

5. **Context pressure at exactly threshold**: Agent at 70% when threshold is 70.
   - **Handling**: Current behavior (>=) preserved. PM decides to reboot.

### Upgrade & Migration

- This is a **breaking change** for the wrapper format. Old wrappers will NOT work with new health_check.py expectations (heartbeat vs status string) unless transition code is included.
- The transition code in health_check.py (handle both formats) should be removed after one version cycle (e.g., v0.25.0 removes old format support).
- Users running SquidSquad on other projects: their wrappers will regenerate on `compose.py install`. If they have custom wrapper modifications, those will be lost.
- `compose.py upgrade` (if it exists) should handle this automatically.

### Open Questions

1. **Should cycle_post.py's `_do_restart_sentinel()` be removed?** The issue spec says agents don't self-restart. But the cycle runner's `restart_needed` field in cycle-output.json is used by agents to signal "I need a restart." In the new model, should agents still be able to signal this? Or should they just checkpoint working state and trust PM to notice context pressure?
   - **Recommendation**: Keep it but add a guard — only allow if context pressure > threshold. This prevents agents from self-restarting for arbitrary reasons while preserving the "I'm running out of context" safety valve.

2. **Should .stop sentinel stay?** The issue spec doesn't mention it. It's a clean way for humans to stop agents without killing processes.
   - **Recommendation**: Keep it. Simple, useful, no complexity cost.

3. **Watchdog removal — is anything else importing it?** Grep shows only `test_watchdog.py` imports it. Safe to remove.
   - **Verified**: Only `tests/test_watchdog.py` and vault decision record reference it.

4. **PM runs reboot_agent.py directly when DM absent — is this safe?** PM is a claude agent running inside a wrapper. If PM calls `reboot_agent.py skill`, it kills the skill agent's claude process. The wrapper respawns it. PM continues its own cycle. Should work.
   - **Recommendation**: Yes, safe. PM calls it via bash, waits for completion, continues.

5. **Should the simplified wrapper still auto-restart on crash (no sentinel)?** The issue spec says "no sentinel = exit cleanly." But if claude crashes (exit code != 0), the old wrapper would restart it. The new one would just exit.
   - **Recommendation**: Keep ONE restart attempt on crash (no sentinel, non-zero exit). If it crashes again immediately, exit for real. This prevents permanent death from transient errors without the 50-restart loop complexity. Alternatively, leave crash recovery entirely to PM boot_remote.py — PM detects dead heartbeat, boots agent.
   - **Issue spec says**: "On exit: no sentinel -> cleanup (rm PID, write health=dead)." So: no auto-restart on crash. PM handles it.

6. **boot_remote.py still needed?** Yes — it's the "spawn agent in new terminal" tool. reboot_agent.py restarts existing agents; boot_remote.py starts agents that aren't running at all.

### Capability Gaps

1. **No automatic crash recovery**: With the 50-restart loop removed and no watchdog, a crashed agent stays dead until PM's next cycle detects it (up to 30 minutes). This is acceptable per the issue spec — PM monitors health each cycle.

2. **No context pressure auto-restart**: The wrapper no longer watches context pressure. PM must detect it during its health check step. If PM is the one with high pressure, PM must self-checkpoint and signal for its own restart via the sentinel mechanism.
   - **Gap**: Who restarts PM? PM can't reboot itself via reboot_agent.py.
   - **Mitigation**: PM writes `.restart` sentinel for itself. Wrapper detects it and respawns. This is the one case where self-restart sentinel is still needed.

3. **No template change auto-restart**: Watchdog detected template mtime changes. In new model, DM handles this after shipping. If DM is absent, PM handles it. If no template change is shipped (manual edit), no agent detects it until next restart.
   - **Acceptable**: Template changes should always go through DM shipping flow.
