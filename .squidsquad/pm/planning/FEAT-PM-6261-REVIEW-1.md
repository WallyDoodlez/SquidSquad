## compose.py L1 Handling

L1 content lives at `references/roles/instructions.md`. In `_assemble_claude()`, compose.py reads L1 as raw text and concatenates it (verbatim) with L2 and L3 text into a string, which is written to a temp file. Then `_resolve_includes_with_manifest()` runs on that temp file and resolves ALL `{{include:}}` directives found anywhere in the assembled string — including any that might exist in L1 text.

**Critical implication**: If tracker-protocol content is inlined as plain prose into L1 instructions.md (no `{{include:}}` directive), it is passed through verbatim — NO `<!-- sub-skill: tracker-protocol -->` wrapper markers are emitted. The content appears in the composed output but has no section markers. This is fine for agent behavior, but any test or tooling that asserts the presence of those markers will break.

**Alternative**: If the plan instead adds `{{include: common/tracker-protocol}}` to L1 instructions.md, it WOULD be resolved and markers WOULD be emitted — but the source file would still need to exist, defeating the deletion goal of AC-1. Therefore inlining is the only viable option, and tests must be updated.
