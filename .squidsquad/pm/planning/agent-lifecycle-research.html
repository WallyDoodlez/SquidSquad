Agent Lifecycle — Boot Research

Investigation into how agent boot/spawn works and what caused multiple instances to spawn simultaneously.

TL;DR: Three bugs found. The boot lock was removed in #2183 with no replacement, so two concurrent boot calls both spawn terminals. The heartbeat format changed but boot_remote.py wasn't updated, causing false "needs boot" for running agents. Stale .restart sentinels cause extra spawns on fresh boots.

3. Heartbeat Format Mismatch (PM-Specific)

The wrapper heartbeat writes a raw epoch number to .health. But boot_remote._needs_boot() only understands named statuses. This causes false "needs boot" for running agents.

Two bugs compound: heartbeat format unrecognized + PID file encoding wrong = boot_remote thinks a running agent is dead.

4. Stale .restart Sentinel

reboot_agent.py writes a .restart file. If the agent dies before processing it, the sentinel persists. The next fresh boot finds it and does an unwanted extra respawn.

The .restart sentinel has no TTL or timestamp. It can trigger a respawn weeks after the original reboot request.

Bugs Summary

HIGH — Bug 1: No Boot Lock

What: boot_remote.py has no inter-process lock. The old lock was removed in #2183 with no replacement.

Effect: Two concurrent callers both see "dead" and both spawn terminals. Wrapper catches duplicates but terminals still flash open.

Fix options: (a) Restore file-based boot lock with TTL, (b) Per-agent .booting sentinel written by boot_remote before spawn, or (c) atomic .health = "spawning" written by boot_remote (not wrapper) before _spawn_terminal().

HIGH — Bug 2: Heartbeat Epoch Not Parsed

What: _needs_boot() only handles named statuses (alive, dead, booting...). Wrapper heartbeat writes raw epoch. Falls through to PID fallback, which fails on Windows (UTF-16).

Effect: boot_remote thinks a running agent (PM) is dead. Could trigger false re-boot of an alive agent.

Fix: _read_health_file() should detect numeric-only content as heartbeat epoch and treat as "alive" if recent (within 15s), "dead" if stale. Also fix _read_pid_file() to handle UTF-16.

MEDIUM — Bug 3: Stale .restart Sentinels

What: reboot_agent.py writes .restart but if the agent dies before processing it, the sentinel persists indefinitely.

Effect: Next fresh boot finds the stale sentinel and does an unwanted extra respawn after first claude exits.

Fix: Either (a) boot_remote cleans stale .restart files when booting a dead agent, or (b) write a timestamp into the sentinel and have the wrapper ignore sentinels older than N minutes.
