# FEAT-PM-2493 Research — Setup wizard creates per-agent working directories for multi-agent execution

## Summary
This research reviewed how SquidSquad currently handles “multi-agent” execution paths and why agents collide: the generated boot scripts always `cd` to the *same* git toplevel (`git rev-parse --show-toplevel`), then perform git operations like `git checkout` in that shared working directory (see `references/templates/start-role.sh:4` and branch switching at `references/templates/start-role.sh:75-86`; similarly in PowerShell at `references/templates/start-role.ps1:4-6` and `83-94`). With multiple agents in one repo, concurrent `git checkout`/`pull`/`commit` operations will race and break each other.

The codebase already has a concept of “per-agent clone roots” via `.squidsquad/.local-config` (generated by `references/scripts/compose.py:416-438`) and consumers that read it (`references/scripts/health_check.py:71-106`, `references/scripts/boot_remote.py:47-83`, `references/scripts/reboot_agent.py:35-46`). There is also a newer shared location `~/.squidsquad/clones/` that `health_check.py` and `boot_remote.py` prefer over `.local-config` (`health_check.py:74-92`, `boot_remote.py:50-68`). Recommendation: implement per-agent isolated working directories using **git worktrees** (lightweight, shared object store) and have the wizard scaffold them + write clone/worktree paths into `~/.squidsquad/clones/<role>` (preferred) and/or `.squidsquad/.local-config` (legacy). Keep PM in the primary repo root; all other agents run from their own worktree directories.

Primary risks: Windows path handling (PowerShell `Start-Job` cwd gotcha), ensuring boot scripts `cd` into the correct worktree (not “git toplevel”), and ensuring state/health checks still find `.squidsquad/<role>/*` across multiple worktrees.

## Impact Analysis
- **Files touched**:
  - `references/scripts/wizard.py` — add a new mechanical step/command to create per-agent worktrees/clones and persist mappings (wizard already scaffolds `.squidsquad/` and `.local-config` at `wizard.py:889-909`).
  - `references/scripts/compose.py` — extend `generate_local_config()` (`compose.py:416-438`) to emit per-agent paths (not all pointing to `target_root`) when wizard provides them.
  - `references/templates/start-role.sh` — change initial `cd "$(git rev-parse --show-toplevel)"` (`start-role.sh:4`) to `cd` into the agent’s assigned worktree path (from `~/.squidsquad/clones/<role>` or `.squidsquad/.local-config`).
  - `references/templates/start-role.ps1` — same change for `$repoRoot = git rev-parse --show-toplevel` + `Set-Location $repoRoot` (`start-role.ps1:4-6`).
  - `references/scripts/reboot_agent.py` — currently reads only `.squidsquad/.local-config` in the *current repo* (`reboot_agent.py:35-46`); should be updated to also read `~/.squidsquad/clones/` like `health_check.py` does.
  - Potentially `references/scripts/add_role.py` — today it creates a full clone via `git clone --local` (`add_role.py:205-210`); could be extended/optioned to create a worktree instead.
  - Tests likely impacted/added:
    - `tests/test_start_scripts.py` (exists) — will need updates to assert new boot-script behavior.
    - New tests around wizard worktree creation and path mapping.

- **Behavior changes**:
  - Boot scripts no longer assume “current directory is the repo root”; they must resolve an agent-specific root and `cd` there before any git ops.
  - Wizard/setup will create per-agent working directories (preferably worktrees) for non-PM agents, preventing `git checkout` collisions.
  - `.local-config` (and/or `~/.squidsquad/clones/`) becomes authoritative for “where each agent runs”.

- **Dependencies**:
  - Requires `git worktree` availability (git ≥ 2.5; practically ubiquitous).
  - On Windows, PowerShell scripts must use absolute paths when spawning background jobs (align with vault learning).
  - Existing consumers already parse `~/.squidsquad/clones/` in `health_check.py` and `boot_remote.py`; `reboot_agent.py` lags behind.

## Side Effects
- **Risk 1**: Worktree + `.squidsquad/` bus duplication/consistency — Severity: H — Mitigation: decide whether `.squidsquad/` is shared (symlink/junction) or duplicated per worktree; if duplicated, cross-agent coordination breaks unless state is centralized elsewhere. Consider making `.squidsquad/` live only in PM repo and have other worktrees link to it (Windows junction / POSIX symlink) or migrate more state to the existing state bus worktree (`references/scripts/state_bus.py`).
- **Risk 2**: Boot scripts still switching branches in each worktree — Severity: M — Mitigation: keep branch switching but isolated per worktree; ensure `WORKING_BRANCH` logic remains correct (`start-role.sh:75-86`, `start-role.ps1:83-94`).
- **Risk 3**: Path mapping drift between `.local-config` and `~/.squidsquad/clones/` — Severity: M — Mitigation: pick one as source of truth (recommend `~/.squidsquad/clones/` since `health_check.py`/`boot_remote.py` already prefer it) and generate/update it during wizard.

## Edge Cases
- **Windows path with spaces**: Worktree paths like `C:\Users\...\My Project\agent-skill` must be quoted everywhere; PowerShell `Start-Process` and `Set-Location` must use proper quoting/`Join-Path`.
- **Missing mapping for a role**: If `~/.squidsquad/clones/<role>` and `.local-config` lack an entry, boot script should fall back to `git rev-parse --show-toplevel` (current behavior) and warn.
- **Worktree already exists**: Wizard should be idempotent: detect existing directories and either reuse or prompt (similar to `wizard.detect_existing_install()` behavior at `wizard.py:131-180`).
- **Git on Windows + junctions/symlinks**: If sharing `.squidsquad/` via links, ensure git doesn’t treat it as unsafe or break permissions; prefer junctions on Windows if symlink privileges are an issue.

## Integration Risks
- **Health check across clones/worktrees**: `health_check.py` already reads per-role clone roots from `~/.squidsquad/clones/` first (`health_check.py:74-92`) and then checks `.squidsquad/<role>/.health` under that root (`health_check.py:233-235`). If `.squidsquad/` is only in PM repo and not present in each worktree, health check will fail unless paths point to PM repo for state, or state is linked into each worktree.
- **Remote boot**: `boot_remote.py` uses clone path mapping (`boot_remote.py:47-83`, `_get_clone_path` at `boot_remote.py:123-127`) and spawns terminals with `-d <clone_root>` on Windows Terminal (`boot_remote.py:279-297`). This will work if clone_root is the worktree root and contains `.squidsquad/start-<role>.*`.
- **Reboot**: `reboot_agent.py` currently only reads `.local-config` in the current repo (`reboot_agent.py:35-46`), so it may reboot the wrong instance in a multi-worktree setup unless updated.

## Upgrade & Migration
- **New config values**: none required (could be optional), but consider adding a wizard spec field like `agents[].workdir_strategy: worktree|clone|shallow` with default `worktree`.
- **New files**: likely:
  - `~/.squidsquad/clones/<role>` entries (already supported by `health_check.py`/`boot_remote.py`).
  - Worktree directories on disk (outside repo), e.g. `../<project>-<role>` or `.squidsquad/worktrees/<role>` depending on chosen layout.
- **Template changes**: boot templates must `cd` to role-specific root instead of `git rev-parse --show-toplevel` (`references/templates/start-role.sh:4`, `references/templates/start-role.ps1:4-6`).
- **Upgrade steps**:
  - Wizard upgrade path should: (1) create worktrees for configured agents, (2) write mappings to `~/.squidsquad/clones/` and `.squidsquad/.local-config`, (3) regenerate boot scripts.
- **Graceful degradation**: If user doesn’t upgrade, system remains single-repo and continues to collide; scripts should still support legacy `.local-config` and fallback-to-toplevel behavior.

## Open Questions
- **Q1**: Should `.squidsquad/` be shared across all worktrees (link to PM repo) or duplicated per worktree? — **Why**: The coordination bus is currently `.squidsquad/` on main (per vault decision); duplicating it breaks cross-agent visibility, but sharing it requires filesystem links and careful git-ignore/commit behavior.
- **Q2**: Where should worktrees live by default on Windows? — **Why**: Long paths and permissions can break; choosing a short, predictable base (e.g. sibling dirs like current `add_role.py` does at `add_role.py:166-169`) reduces failures.
- **Q3**: Do we standardize on `~/.squidsquad/clones/` and deprecate `.local-config`? — **Why**: Multiple scripts already prefer shared_fs clones; inconsistent sources will cause agents to boot in wrong directories.

## Recommendation
**Feasible with caveats**. Use **git worktrees** for per-agent isolation (lightweight, fast, minimal disk) and make the wizard generate:
1) per-agent worktree directories (PM stays in primary repo),
2) authoritative role→path mapping in `~/.squidsquad/clones/` (via `references/scripts/shared_fs.py write-clone`, which already exists),
3) updated boot templates to `cd` into the mapped path before any git ops.

Key caveat to resolve early: whether `.squidsquad/` state is shared (linked) or per-worktree; health/boot/reboot scripts assume `.squidsquad/<role>/...` exists under each clone root, so the mapping and filesystem layout must match that assumption or those scripts must be adapted.
