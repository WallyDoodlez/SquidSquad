## Gaps Found

### GAP 1: `cycle_post.py` — DM-absent CHANGELOG conditional is still live code (not just comments)

**File**: `references/scripts/cycle_post.py`, lines 437-453
**What it does**: `_do_version_bump()` checks `if not dm_dir.exists()` before writing a CHANGELOG entry. This is a runtime fallback behavior — when DM is absent, the script writes a bare CHANGELOG entry. When DM is present, it skips this (DM writes richer entries).

**Why it's a gap**: The plan only mentions updating the *comment* on line 437 ("DM writes richer CHANGELOG entries. When DM is absent, PM fallback writes the basic shipped list."). But the actual runtime conditional on line 442 (`if changelog.exists() and not dm_dir.exists()`) is dead code that will never execute now that DM is always present. The plan does NOT explicitly say to remove this conditional — it only mentions `config.py` lines 394-401 and `config.py` lines 522-525. This DM-presence runtime check in `cycle_post.py` should be simplified: since DM is always present, remove the conditional and let DM always own CHANGELOG writes (or remove the entire CHANGELOG-writing block from `_do_version_bump` since DM handles it via its own delivery path).

**Risk**: Dead code is benign now but adds confusion and could regress if someone misreads it.

**What it does**: The PM input dict contains `"e2e_test_result": None` with the comment `# PM runs E2E during creative phase if QA absent`. This comment implies PM conditionally runs E2E when QA is absent — exactly the fallback behavior being removed.

**Why it's a gap**: The plan covers removing `qa_present`/`dm_present` fields but does not mention this `e2e_test_result` field or its misleading comment. If PM no longer ever runs E2E (QA always present), the field itself may be vestigial. At minimum, the comment must be updated or the field removed. At most, the field should be dropped from the PM input schema entirely.

### GAP 3: `boot_remote.py` — role detection reads legacy config format

**File**: `references/scripts/boot_remote.py`, lines 128-133
**What it does**: `_get_all_roles()` detects DM presence by matching `**DM**: present` in config.md, and QA by matching `**QA**: always present`. These patterns match the current (post-#6055) config.md format — but they do NOT match the legacy `**PM/QA**: always present` combined format that `_parse_agents_v1` in config.py handles.

**Why it's a gap**: The plan says config.py's `_parse_agents_v1` block (line 394-401, the `if "PM/QA" in agents_text` block) will be removed. But `boot_remote.py` has a parallel implementation of role detection that reads directly from config.md text without going through `config.py` helper functions. After this task, the config.md format will only ever have separate `**PM**`, `**QA**`, and `**DM**` entries (never `**PM/QA**`) — so `boot_remote.py`'s QA detection (line 132: `**QA**: always present`) needs to be verified against the updated format. The plan doesn't mention `boot_remote.py` at all.

**Risk**: If the config.md format changes in how QA is represented (e.g., from `**QA**: always present` to a different format written by the updated `sync_agents()`), `boot_remote.py` would fail to detect QA and would not boot the QA agent.
